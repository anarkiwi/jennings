# Native core

`MPU(memory=NativeMemory())` runs the 6510 in Rust. Any other memory object keeps the
pure-Python deity-informant engine. Wheels ship the native core as `jennings._core`;
an sdist install (no Rust toolchain) has the Python engine only and
`jennings.memory.NATIVE` is false.

## Layout

| Path | Role |
|---|---|
| `crates/jennings-core` | Pure Rust library: `Bus` trait, `Cpu`, `FlatMemory`, `run_until`/`run_to_rts`. No PyO3. |
| `crates/jennings-core/src/access.rs` | `Accesses`: a `Bus` adapter logging data accesses and redirecting chosen instructions' accesses (`Remap`). |
| `crates/jennings-core/src/orbit.rs` | `orbit`: an entry's calls repeated until its state repeats, with their distinct accesses and edges. |
| `crates/jennings-core/src/cpu_gen.rs` | Opcode semantics, generated by `tools/gen_cpu.py`. Do not edit. |
| `crates/jennings-core/src/taint.rs` | `Learn`: each call's locations tainted with the entry locations they came from, by data and control, every call or each census class's first; `trajectory`: locations per call. |
| `crates/jennings-core/src/census.rs` | `Census`: calls sorted into classes by what `Learn` sees of each, with entry snapshots, first-seen edges, exits and written memory, and cell columns. |
| `crates/jennings-core/src/period.rs` | `periods`: first repeats of column sets of a trajectory and where each breaks its period. |
| `crates/jennings-core/examples/calls.rs` | Calls of an entry per second: plain, through a `Census`, and a census-driven `Learn`. |
| `crates/jennings-core/src/flow_gen.rs` | Per-opcode data flow for `taint.rs`, generated by `tools/gen_flow.py`. Do not edit. |
| `crates/jennings-core/examples/bench.rs` | `run_until` throughput on a 64 KiB image (`tools/bench.py --dump IMAGE` writes the playroutine one). |
| `crates/jennings-py` | PyO3 extension `jennings._core`: `NativeMemory`, `Core`. |
| `jennings/devices/mpu6502.py` | `MPU.__new__` returns a `NativeMPU` (py65 surface over `Core`) for a `NativeMemory`. |

## Generated semantics

`tools/gen_cpu.py` emits every opcode's `deity_informant.lifter.template`: its P-Code
with each operand-derived constant bound to an operand expression (`b1`, the word `w`,
`(b1+1)&$FF`, `(b2+1)&$FF`), base cycles, control class and page-cross penalty. The
template's sentinel lifts check every binding; a constant that differs between lifts
without provenance fails generation.

Each opcode becomes one `op_XX` function: operand fetches, the P-Code as straight-line
Rust (`LOAD`/`STORE` whose address derives from SP become stack accesses, the rest data
accesses), the base cycles plus the extra-cycle rule (`cross(base, X|Y)` for `ax`/`ay`/`iy`
penalties, `Cpu::branch` for taken/page-crossing branches) and the control kind. The
control kinds the lifter defers to `PcodeVM.step` (`br`, `jmp`, `jmpind`, `jsr`, `rts`,
`rti`, `brk`, `jam`) are resolved by one `Cpu` method each, mirroring `PcodeVM.step`;
no opcode body is hand-written. Register results stay in locals until after the
instruction's last bus access, and the control resolvers return the new SP/PC rather
than writing them, so the `Cpu` passed to `Bus::sync` is the instruction-start state
throughout its accesses: callbacks read it in place, with no per-instruction copy.
`tests/test_gen_cpu.py` checks regeneration is a no-op.

`tools/gen_flow.py` reads `jennings.dataflow.flow` once per opcode on symbolic locations
(registers, operand bytes, the instruction's loads and stores in order) into
`flow_gen.rs`: each output's and each access address's inputs as a bit mask, each output's
explicit inputs (`vals`, read with `addressed=False`), the opcode's length and control
class. `tests/test_gen_flow.py` checks regeneration is a no-op.

## Access classes

| Access | Examples | `subscribe_to_*` | `observe_data_access` | raster model |
|---|---|---|---|---|
| fetch | opcode, operands | no | no | no |
| data | operand reads/writes, `(zp)` pointer bytes | yes | yes | yes |
| stack | `PHA`/`PLA`/`PHP`/`PLP`, `JSR`/`RTS`/`RTI`/`BRK`, interrupt frames, driver dummy frames | yes | no | — |
| other | interrupt vectors, `JMP (ind)` pointer | yes | no | yes |
| host | `mem[addr]` from Python | yes | no | yes |

Subscriptions follow `ObservableMemory`: callbacks per address in registration order
(deduplicated by `==`), a read callback's non-None result substitutes the value (the last
one wins; memory is not read if any substitutes), a write callback's non-None result is
passed on and stored. `observe_data_access(on_read, on_write, reads=None, writes=None)`
calls `on_read(addr)` after each data load and `on_write(addr, value)` after each data
store (the instruction's value, before write callbacks rewrite it), optionally limited
to address sets: iterables of addresses and/or `range`s, or a `range`. A unit-step `range`
is passed natively as a span, so arming costs the pages previously observed plus the words
the filter covers, never a 64K sweep; `observe_data_access()` clears in the same bound.
`mem.last_load` is the address of the most recent data load.
Both native types take part in cyclic garbage collection: a memory reports its callbacks
and a core its memory, so an owner subscribing its own bound methods is freed with them.

## NativeMemory

- `mem[a]`, `mem[a:b:s]` read through the page table, raster model and read
  subscriptions; assignment accepts ints, bytes-likes or int iterables and goes through
  write subscriptions. `mem.write(start, data)` copies into RAM with no callbacks.
- The buffer protocol exposes the 64 KiB RAM (`bytes(mem)`, `memoryview(mem)`,
  `numpy.frombuffer(mem, numpy.uint8)`), zero-copy.
- `set_page(n, image)` maps 4 KiB page `n` to a read-only 4096-byte image;
  `set_page(n)` maps it back to RAM. Writes always reach RAM (ROM under RAM).
- `mem.io` marks `$D000-$DFFF` as the banked-in I/O page; `raster_model(ntsc)` makes
  `$D011`/`$D012` follow the beam (`cycles // cycles_per_line % lines`, PAL 63×312, NTSC
  65×263) at the cycle count of the instruction's start while `io` is set, as
  `vagrant_moses.cpu.flat_mpu` does; `raster_model(None)` disables it.
- Python is called only for a subscribed or observed address.

## Drivers

`NativeMPU.run_until(max_cycles=None, stop_pcs=None, sp_above=None, stop_on_jam=True,
irq_period=None)` steps with the GIL released until, before an instruction, SP exceeds
`sp_above`, more than `max_cycles` have elapsed, or PC is in `stop_pcs` or a half-open `(lo, hi)` of `stop_ranges`; or, after one, a
JAM ran or a callback set `mpu.stop = True`. `stop_on_irq=True` also stops before an instruction when I is clear (`"irq"`), and
`stop_on_idle=True` after one that leaves PC and SP unchanged (`"idle"`); both are constant-time,
so no `stop_pcs` RAM scan is needed. It returns `"sp"`, `"cycles"`, `"pc"`,
`"jam"`, `"stop"`, `"idle"` or `"irq"`. With `irq_period`, the instruction that brings the cycle count to
`mpu.irq_due` is followed by `irq()` (dropped if I is set, as `MPU.irq()` does) and
`irq_due` advances by the period; it persists across runs (unset: one period from the
run's start), so a playroutine's IRQ cadence never returns to Python. `run_to_rts(pc, acc, max_cycles)` and `run_to_rts_until(pc, acc, pcs,
max_cycles)` are `vagrant_moses.cpu.run_to_rts` and `pysidtracker.emu.run_to_rts_until`
(dummy `$0100` return pushed, stop once SP rises above its start, `pcs` checked before
each instruction). `run_until(..., trace=True)` (returns `(reason, Trace)`) and
`run_to_rts_traced(pc, acc, max_cycles, regs=False)` (returns a `Trace`) record one row per
executed instruction without leaving the native loop: `pc` (uint16) and `cycles` (uint64) at
the instruction's start and, with `regs=True`, `a`/`x`/`y`/`sp`/`p` after it. Columns are
read-only memoryviews, so `numpy.asarray(trace.pc)` wraps them without a copy. `step()` remains correct for callers that step from Python; the
drivers are the fast path.

`run_to_rts_accesses(pc, acc, max_cycles, remap=None)` returns `(Trace, accesses)`: the
trace without registers and every data load and store in order as a read-only uint64
memoryview of `pc << 17 | write << 16 | addr` (`pc` the instruction's start), logged
natively with no callback. `Remap({pc: table}, pointer_opcodes)` redirects the accesses of
the instructions at its PCs: a table holds one int32 per address, -1 accessed as it is, -2
reads 0, else the address the read takes its byte from; a redirected write stores nothing.
The page-zero pointer bytes of an opcode in `pointer_opcodes` (operand + X and operand + X + 1
for `(zp,X)`, operand and operand + 1 for `(zp),Y`, wrapping in page zero) are accessed as
they are. The log keeps the address the instruction named; a data-access observer sees a
redirected read as a load of the address it takes its byte from, and nothing of one that
reads 0. `run_to_rts`,
`run_to_rts_until` and `run_until` take the same `remap=None`, applied without a log
(`Accesses::remapped` in jennings-core). With `bases=True` it returns `(Trace, accesses,
bases)`, `bases` a uint16 memoryview in step with `accesses`: each access's address before
indexing, the operand of an `abs,X`/`abs,Y`/`zp,X`/`zp,Y` instruction, the pointer word
of a `(zp),Y` one (as its first two loads read it, after any remap; those loads are based
on themselves), else the address itself (`Base` and `Accesses::with_bases` in
jennings-core).
`mem.digest(spans=None)` is a 16-byte digest of the RAM in `spans` (as
`observe_data_access` takes them, default all): equal RAM there gives an equal digest, so a
run of calls detects a repeated state without copying memory to Python.

`orbit(pc, acc, max_cycles, limit, keep=None, volatile=None, remap=None)` runs that loop
natively: calls of `pc` (each as `run_to_rts_accesses`, `remap` applied) until the digest of
RAM at `keep` before a call was seen before (`"closed"`), `limit` calls ran (`"open"`), or a
call loads an address of `volatile` (`"volatile"`) or jams (`"jam"`), that call included. It
returns `(end, states, accesses, edges)`: the distinct states, the distinct access keys and
the distinct `pc << 16 | next` of consecutive instructions within a call, both ascending
uint64 memoryviews. Each set is a 64 Ki-bit page per instruction (and direction), so a call
costs its instructions and accesses whatever the orbit's length. `cells`, locations
(addresses, `REG` + a register index), are hashed in place of the RAM at `keep`.

`trajectory(pc, acc, max_cycles, calls, cells, remap=None)` returns `(stop, rows)`: uint8
`[calls, len(cells)]`, the locations at each call's entry. `learn(learner, pc, acc,
max_cycles, calls, remap=None, census=None)` adds calls to a `Learner(control, written,
explicit=False)`
(`control` `{pc: branches}` it is directly control dependent on, `written` the memory a call
may write, `explicit` tainting by data alone, a load's value apart from its address and a
data load of a constant at `pc` as `CONST + pc`, `CONST = 0x20000`, control only into
`gated`). `learner.learned()` returns a dict of little-endian arrays:

| key | dtype | entry |
|---|---|---|
| `persistent` | uint32 | a location some call reads before writing and some call writes |
| `deps` | uint64 | `loc << 32 \| src`: end-of-call `loc` depends on entry `src` (`loc` itself included) |
| `edges` | uint64 | `pc << 16 \| next`, consecutive instructions within a call |
| `sites` | uint64 | `(pc << 2 \| kind) << 18 \| loc`: `loc` taints a data load's (kind 0) or store's (1) address, where control goes (2), or a data store's byte (3) at `pc` |
| `stored` | uint64 | explicit only (else empty), `loc << 32 \| src` over every data store to memory `loc`: `src` taints the byte stored |
| `addressed` | uint64 | as `stored`: `src` taints the store's address |
| `gated` | uint64 | as `stored`: `src` taints the conditions of the branches the store is (transitively) under, and at each call's end those of the branches `loc`'s store sites are control dependent on that ran |
| `exits` | uint16 | a PC that ended a call |
| `written` | uint16 | an address some call wrote |

Locations are addresses, `REG + index` for registers and `CONST + pc` for constants. Both
stop early at a call that does not return (`stop` other than `"sp"`).

`census(census, pc, acc, max_cycles, calls, remap=None)` adds calls to a `Census(cells)`:
`census.calls` and `census.classes` count them and their classes, `census.columns()` holds
each cell's value at each call's entry (one byte per call, cell after cell) and
`census.firsts()` gives `{"edges", "exits", "written"}` as `(items, calls)`, little-endian
uint64 / uint16 / uint16 items in order of first sight with the uint32 call each was first
seen in, so any prefix of the calls has its own sets. Given to `learn` as `census`, the
census must cover the learner's calls from the state this core held at its first: each class's
first call is restored from its snapshot and tainted, the rest only add the implicit flows
learned since their class last ran ([coverage.md](coverage.md#learning-once-per-class)).

`periods_of(rows, subsets)` takes a C- or Fortran-contiguous uint8 `[calls, cells]` array and
returns per column list `((preperiod, period), t)`: the first row equal on those columns to an
earlier one, and the first `t` from the preperiod whose rows `t` and `t + period` agree there
while rows `t + 1` and `t + 1 + period` do not (None for either where there is none).

The drivers above run on a memory with nothing mapped or watched (`FlatMemory::plain`) through
`RamBus`, its RAM without page checks, and `run_to_rts` without stop PCs runs a loop of its own
checks only; both behave as the general path. See
[coverage.md](coverage.md#components-and-cover-calls).

A driver claims its core and memory for the running thread. Other threads touching
either get `RuntimeError` until it returns; independent MPUs run in parallel threads.
Callbacks re-acquire the GIL, see the registers as at the start of the executing
instruction, and may not assign registers. An exception from a callback ends the
current instruction (with no further callbacks) and is raised from the driver or
`step()`.

## Differences from the Python engine

- Fetches never reach subscriptions; the Python engine reads opcode bytes through an
  `ObservableMemory` several times per step (JAM check, cache key, lift).
- The `(zp),Y` page-cross penalty uses the loaded pointer; `PcodeVM._resolve` re-reads
  it from memory after the instruction (equal unless a callback rewrites the pointer).
- Host writes must be bytes (`ValueError` otherwise); callback results are masked to 8 bits.

## Adopting NativeMemory

`vagrant_moses.cpu.flat_mpu`: build a `NativeMemory(ram)`, `set_page` the BASIC, KERNAL
and CHARGEN images per `banking($01)` and set `mem.io`, re-banking from one write
subscription on `$00`/`$01` (and a read subscription for `port_read`), and replace the
raster subscription with `mem.raster_model(ntsc)`. `run_to_rts` becomes
`mpu.run_to_rts(...)` when `mpu.native`.

`pysidtracker.emu`: drop the `mpu._vm` swap in `observe_data_access` for
`mem.observe_data_access(on_read, on_write, reads=..., writes=...)`; `SidWriteLog` can
observe only the SID writes and read `mem.last_load` instead of observing every load.
Its VM hook also reports `PHA`/`PLA`/`PHP`/`PLP` page-1 accesses (they are P-Code
`LOAD`/`STORE`); the native observer, per the hook's documented contract, does not.
The native core's bus sees data accesses only. The Python engine also makes the NMOS dummy
accesses (the throw-away reads of indexed accesses, a read-modify-write's dummy write, the byte
after a one-byte opcode) unless `mpu.bus_dummies = False`; set it when the memory is a machine
that places them on its own cycles (vagrant-moses does) or to observe data accesses as the
native observer does.
`wire_mpu`'s SID subscriptions carry over unchanged. `run_to_rts_until` becomes
`mpu.run_to_rts_until(...)`.
